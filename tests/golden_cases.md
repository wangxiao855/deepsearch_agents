# 回归用例（改完提示词或工具后，逐条跑一遍）

判断标准只看「输出里有没有这些东西」，不看文采。任何一条不满足，说明该类约束没有生效。

---

## 用例 1：单车型完整四维（必过）

**输入**
```
比亚迪秦PLUS DM-i 现在落地多少钱，值得买吗？
```

**必须出现**
- [ ] 一句话结论，且明确「适合谁 / 不适合谁」
- [ ] 价格分档：至少区分「官方指导价」与「终端裸车/成交价」，且各自带**日期**
- [ ] 月销量，且标明月份与口径（厂商/乘联会/上险量之一）
- [ ] 口碑正反并列，至少 3 个不同来源
- [ ] 售后：质保分项（整车 / 三电 / 是否限首任车主）至少写出 2 项
- [ ] 车主反馈：问题带频次或样本量表述
- [ ] 竞品对比表（≥2 款）
- [ ] 到店必问清单
- [ ] 末尾有出处列表

**禁止出现**
- [ ] 「大概 15 万」「通常都有 L2」这类无出处的模糊数字
- [ ] 「闭眼买」「绝对没问题」「同级最强」
- [ ] 把指导价与落地价混成一个数

## 用例 2：投诉样本边界（最容易翻车，必过）

**输入**
```
比亚迪秦L 投诉多吗？质量靠不靠谱？
```

**必须出现**
- [ ] 明确说明这是「本地投诉样本（约 597 条，快照 2026-10-14）」
- [ ] 给出样本内的具体案例（带投诉编号）或明确说「样本中未检索到」
- [ ] 明确区分「有人投诉了某事」与「这款车普遍有问题」

**禁止出现**
- [ ] 「这款车投诉量高 / 投诉率高」
- [ ] 与其他车型比较投诉数量、排名
- [ ] 因为样本里没有案例就得出「这车没问题」的结论

---

## 用例 3：模糊需求（考察归一与追问）

**输入**
```
15万左右家用SUV推荐
```

**必须出现**
- [ ] 不直接抛 5 个问题，而是先给 3 款候选 + 一句对比结论
- [ ] 追问不超过 2 个问题（能源形式 / 用途或年里程）
- [ ] 候选车型的价格都带区间与口径

---

## 用例 4：多轮追问（考察会话记忆）

**输入序列**
```
1. 理想L6 现在什么价？
2. 那它保养贵吗？
3. 和问界M7 比呢？
```

**必须出现**
- [ ] 第 2 轮不重复问「你要问哪款车」，直接回答 L6 的保养
- [ ] 第 3 轮理解「它」指 L6，输出 L6 vs M7 对比
- [ ] 三轮之间价格口径一致，不出现前一轮 25 万后一轮 23 万却无解释

---

## 用例 5：无数据车型（考察不编造）

**输入**
```
（任选一款本地投诉库与搜索都很难覆盖的小众车型，例如某新势力限量版）
```

**必须出现**
- [ ] 明确写「未获取到」的字段，并说明建议去哪个渠道确认
- [ ] 仍能给出「能确认的部分」（如官方指导价若能查到）

**禁止出现**
- [ ] 编造配置参数、销量数字、质保条款
- [ ] 用「据说」「一般来说」填补空缺

---

## 用例 6：报告交付（考察按需出文件）

**输入**
```
把上面的结论整理成一份报告，我要发给家里人看
```

**必须出现**
- [ ] 调用 `generate_markdown` 生成 `.md`，文件名有业务含义（含车型）
- [ ] 文件出现在 `output/session_{thread_id}/` 下，前端侧栏可见可下载
- [ ] 用户没有要 PDF 时不生成 PDF

---

## 附：不需要每次都跑的检查

- 前端四维进度条是否按 行情→口碑→售后→车主 点亮
- 出处卡片是否能点开原文
- 「新对话」是否清空上下文（前端消息 + 后端记忆）
